### Installation

```bash
npm i minotor
```

Use the TypeScript API for applications and data processing. Parsing GTFS feeds requires Node.js; routing and stop search also run in the browser and React Native.

An optional [CLI](#cli-usage) is available for debugging.

### Data sources

[opentransportdata.swiss](https://opentransportdata.swiss) provides a [GTFS feed for Switzerland](https://data.opentransportdata.swiss/en/dataset/timetable-2026-gtfs2020) that is supported by the library.

```bash
wget https://data.opentransportdata.swiss/en/dataset/timetable-2026-gtfs2020/permalink -O gtfs-feed.zip
```

GTFS feeds from other providers and other regions can be used as well but are not officially supported yet.

### GTFS Feed parsing

Parse the Swiss GTFS feed for the current day using the extended profile:

```typescript
import { GtfsParser, extendedGtfsProfile } from 'minotor/parser';

const parser = new GtfsParser('gtfs-feed.zip', extendedGtfsProfile);
const timetable = await parser.parseTimetable(new Date());
const stopsIndex = await parser.parseStops();
```

Note that this operation can take a few minutes for large GTFS feeds and requires a Node.js environment.

`timetable` and `stopsIndex` are objects. Call `.serialize()` on each to produce protobuf binary data, then load it with `Timetable.fromData()` and `StopsIndex.fromData()` from `minotor`. Generate and load both assets together with the same Minotor version so that their stop IDs and binary formats match.

Times and durations use whole minutes; departure and arrival times are measured from midnight on the timetable's service day.

#### Virtual transfers

Some feeds leave nearby stops unconnected in `transfers.txt`. Pass a transfer generator to the parser to add missing walking connections before serializing the timetable:

```typescript
import {
  GtfsParser,
  StraightLineTransferGenerator,
  extendedGtfsProfile,
} from 'minotor/parser';

const parser = new GtfsParser(
  'gtfs-feed.zip',
  extendedGtfsProfile,
  new StraightLineTransferGenerator({ maxDistanceMeters: 500 }),
);

const timetable = await parser.parseTimetable(new Date());
const stopsIndex = await parser.parseStops();
```

The built-in generator estimates walking time from straight-line distance. You can tune `walkingSpeedKmh`, `detourFactor`, and `changePenaltyMinutes`, or supply a custom `TransferGenerator` backed by a pedestrian routing engine.

### Stop Search

Lookup stops by name:

```typescript
const origins = stopsIndex.findStopsByName('Fribourg');
```

Partial and fuzzy matches are also supported:

```typescript
const destinations = stopsIndex.findStopsByName('Moles');
```

Query stops by ID:

```typescript
const stopFromId = stopsIndex.findStopBySourceStopId('Parentch:1:sloid:92374');
```

Or by location (e.g. find the 5 closest stops within 500m):

```typescript
const nearbyStops = stopsIndex.findStopsByLocation(46.80314924, 7.1510478, 5, 0.5);
```

### Routing

Use `Query` with `router.route()` for a fixed departure time, or `RangeQuery` with `router.rangeRoute()` to compare journeys across a departure-time window. Both use the same timetable and stops index.

#### Point queries

A point query finds the earliest-arrival journey when you are ready to depart at a specific time:

```typescript
import { Query, Router } from 'minotor';

const router = new Router(timetable, stopsIndex);

const origin = stopsIndex.findStopBySourceStopId('Parentch:1:sloid:4100');
const destination = stopsIndex.findStopBySourceStopId('Parentch:1:sloid:4748');

if (!origin || !destination) {
  throw new Error('Origin or destination not found in this feed');
}

const query = new Query.Builder()
  .from(origin.id)
  .to(destination.id)
  .departureTime(8 * 60) // Minutes since midnight
  .maxTransfers(5)
  .build();

const result = router.route(query);
```

Get the earliest-arrival route to the destination, or `undefined` if it is unreachable:

```typescript
const bestRoute = result.bestRoute();
```

Look up an arrival without reconstructing the route. The result contains `arrival` (minutes from midnight) and `legNumber`, or is `undefined` if the stop was not reached:

```typescript
const arrival = result.arrivalAt(destination.id);
```

Both `bestRoute()` and `arrivalAt()` can take another target stop and an optional lower transfer limit. A query with destinations can prune the search, so omit `.to()` when you need results for the whole network (see [Reachability](#reachability)).

#### Range queries

Use a range query when departure time is flexible. It returns Pareto-optimal journeys in the inclusive window between `departureTime` and `lastDepartureTime`: a journey is excluded if another departs no earlier and arrives no later, with at least one strict improvement. This is a set of useful departure/arrival tradeoffs, not every scheduled departure.

Using the router, origin, and destination from the point-query example:

```typescript
import { RangeQuery } from 'minotor';

const rangeResult = router.rangeRoute(
  new RangeQuery.Builder()
    .from(origin.id)
    .to(destination.id)
    .departureTime(8 * 60) // Window starts at 08:00
    .lastDepartureTime(10 * 60) // Window ends at 10:00
    .maxTransfers(3)
    .rangeOptions({ optimizeBeyondLatestDeparture: false })
    .build(),
);

const journeyCount = rangeResult.size;
const earliestArrival = rangeResult.bestRoute();
const latestDeparture = rangeResult.latestDepartureRoute();
const shortestJourney = rangeResult.fastestRoute();

// Routes are yielded earliest-departure-first.
for (const route of rangeResult.routes()) {
  console.log(route);
}

// Individual routing runs are yielded latest-departure-first.
for (const { departureTime, result } of rangeResult) {
  console.log(departureTime, result.bestRoute());
}
```

The route-selection methods return `undefined` when no journey is found. `bestRoute()` minimizes arrival time; `fastestRoute()` minimizes travel duration from origin departure to destination arrival.

### Reachability

Omit `.to()` to explore the whole network. For a fixed departure time, `arrivals()` yields each reachable stop's ID, arrival time, and leg count:

```typescript
const networkResult = router.route(
  new Query.Builder()
    .from(origin.id)
    .departureTime(8 * 60)
    .maxDuration(60)
    .build(),
);

const arrivals = [...networkResult.arrivals()];
```

For a flexible departure window, a range query can also find the shortest travel duration to each stop:

```typescript
const networkRangeResult = router.rangeRoute(
  new RangeQuery.Builder()
    .from(origin.id)
    .departureTime(8 * 60)
    .lastDepartureTime(10 * 60)
    .maxDuration(60)
    .rangeOptions({ optimizeBeyondLatestDeparture: false })
    .build(),
);

const earliestArrivals = [...networkRangeResult.arrivals()];
const shortestDurations = [...networkRangeResult.shortestDurations()];
const durationToDestination = networkRangeResult.shortestDurationTo(destination.id);
```

Each shortest-duration entry includes `duration` in minutes. In queries without destinations, use these per-stop results; `routes()` has no default destinations to return, and route-selection methods such as `bestRoute(destination.id)` need an explicit target.

### CLI Usage

**The CLI is for debugging purposes.** It provides local feed parsing, interactive queries, and inspection tools to investigate data and routing behavior. Use the TypeScript API above for application integrations and production data processing.

It can be installed globally:

```bash
npm i -g minotor
```

Parse GTFS data for a day and output the timetable and stops index, using the extended GTFS profile (`minotor parse-gtfs -h` for more options):

```bash
minotor parse-gtfs gtfs-feed.zip -d 2026-11-23 -t timetable.bin -s stops.bin -p extended
```

Note that this operation can take a few minutes for very large GTFS feeds.
Without extra parameters it saves the timetable and stops index for the current day in `/tmp` as binary protobufs. Add `--virtual-transfers-radius 500` to generate walking transfers between nearby stops within 500 meters.

Run the REPL to query the router or the stop index (`minotor repl -h` for more options):

```bash
minotor repl -t timetable.bin -s stops.bin
```

Search stops (`.find -h` for more options):

```bash
minotor> .find moleson
```

Query routes (`.route -h` for more options):

```bash
minotor> .route from fribourg to moleson at 08:00
```

Inspect a stop by internal ID, source ID, or name, or inspect a route by ID:

```text
minotor> .inspect stop fribourg
minotor> .inspect route <id>
```
